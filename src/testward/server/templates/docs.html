Set up testward

1. Try it on a branch, no account

pip install git+https://github.com/zaidwhy/testward
git checkout your-branch
testward replay --base origin/main --command "pytest {file} -q"

Exit code 0 means every changed test held. Exit code 1 means at least one old test fails on the new code. Exit code 2 means the replay could not run, and the message says why.

The working tree must have no uncommitted changes to tracked files: the replay rewrites test files in place and puts them back afterwards.

2. Run it on every pull request

{% include "workflow.html" %}

Leave out server and the env block to run without sign-offs. The check then fails whenever an old test fails on the new code.

3. Add sign-offs

Create an account, create a project, and save its token as the TESTWARD_TOKEN secret. When a replay needs sign-off, the project page shows the test file, the output of the old test and a form for the reason. Re-run the job after signing off and it passes.

Secrets are not given to pull requests from forks, so those run without sign-offs.

Settings

Put .testward.toml on the base branch. The copy on the base branch is the one that counts; a pull request cannot change its own test command.

command = "pytest {file} -q"      # {file} is each changed test file
setup = "pip install -e ."         # optional, run after switching to the base code
timeout_seconds = 300              # per test file, 1 to 3600
max_files = 40                     # changed test files replayed per run, 1 to 200
test_globs = ["test_*.py", "*_test.py", "*.test.*", "*.spec.*"]
support_globs = ["conftest.py", "*.snap"]   # restored with the tests, not run alone

What gets sent to this server

Commit ids, test file paths, exit codes, the test command, and the last 4,000 characters of output from each failing replay. No source code. Pass --no-logs (Action input send-logs: false) to keep test output out of the report.
